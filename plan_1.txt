# SignSpeakPH Repository Improvement Plan

## Context

The user requested an analysis of what needs improvement in the SignSpeakPH repository. This is a Filipino sign language recognition web application that evolved from experimental Jupyter notebooks into a production Flask app. The analysis reveals significant technical debt across git workflow, code organization, testing, and model-data alignment issues.

**Current State:**
- Repository: https://github.com/Emman0027/SignSpeakPH.git
- Current branch: `New_signs` (7 commits ahead of main)
- 26 total commits with poor commit message quality
- Zero test coverage
- Mixed development/production artifacts
- Model trained for 22 signs but only 5 are actually deployed

---

## Critical Issues Identified

### 1. **Git Workflow & Commit Quality Problems**

**Symptoms:**
- Sequential "fix" commits: `fix index`, `error-fixing`, `error_fix`, `fix`
- Non-descriptive messages lacking context
- Large monolithic commits (743-1,289 line changes across 6-12 files)
- Zero commits with proper attribution (Co-Authored-By tags missing)
- Only 1 pull request in entire history
- Main branch is 7 commits behind `New_signs`
- No branch protection on main

**Root Cause:** Direct commits without review, changes not tested before committing, lack of established git workflow standards.

### 2. **Model-Data Mismatch (CRITICAL)**

**The Problem:**
- `labels.json` contains only **5 signs**: `["kamusta", "salamat", "mahalkita", "oo", "hindi"]`
- `constants.py` defines **22 signs** with complete descriptions
- Deployed model (`action.tflite` - 1.1MB) was trained on a different sign set
- This means 17 signs are defined in UI but cannot be recognized

**Impact:** Users see 22 signs in the guide but model only recognizes 5, creating broken UX.

### 3. **Repository Structure Issues**

**Development artifacts mixed with production code:**
- 3 Jupyter notebooks (5.4MB total) at root level
- `backups/` directory with 4 backup files committed to git
- Temporary fix scripts: `fix_import.py`, `fix_logging.py`, `fix_index_html.py`
- `.ipynb_checkpoints/` tracked in git (despite .gitignore entry)
- Test data (`0.npy`, `compare_extraction.py`) at root
- No organized `src/`, `tests/`, or proper package structure

### 4. **Dependency Management Problems**

**Two conflicting requirements files:**
- `requirements.txt` (6 packages, production-focused)
- `requirements-training.txt` (149 packages, includes full TensorFlow)
- Malformed certifi version: `certifi==2026.1.4` (future date)
- No clear dev/prod separation

### 5. **Zero Test Coverage**

- No unit tests for any module
- No integration tests for Flask endpoints
- No model accuracy validation tests
- No CI/CD pipeline
- No code quality tools (linting, formatting)

### 6. **Branch Cleanup Needed**

**Stale branches:**
- `fetchtrial` - unclear purpose, merged via PR #1
- `no-holistic` - experimental, appears merged
- `claude/nifty-fermi-55947f` - temporary Claude session branch

### 7. **Security & Production Concerns**

- Single worker in Dockerfile (`--workers 1`)
- No monitoring/logging infrastructure
- No error tracking (Sentry, etc.)
- No rate limiting documentation
- 120s timeout may need tuning

## Additional Technical Debt Findings

### Binary Files in Git (HIGH PRIORITY)
**Critical Issue:** Large model files committed directly:
- `action.h5` - 2.8MB
- `action.keras` - 2.8MB  
- `action.tflite` - 1.2MB
- `0.npy` - 2.2KB

**Action:** These should be in `.gitignore` and stored via Git LFS or external storage (S3, CDN). Each commit containing these files bloats repository permanently.

### Code Issues Found
1. **Duplicate import** in `app.py`:
   - Line 63: `from constants import SIGN_INFO`
   - Line 87: `from constants import SIGN_INFO` (duplicate)

2. **Hardcoded values** throughout:
   - `app.py:90` - 5MB upload limit
   - `app.py:232` - host/debug flags
   - `templates/index.html` - JS magic numbers (320x240, sequence length 30, 33ms interval)

3. **Unpinned dependency**: `numpy<2.0` should be exact version in requirements.txt

4. **Local file path** in requirements-training.txt line 89:
   ```
   packaging @ file:///C:/miniconda3/conda-bld/packaging_1761049101700/work
   ```
   This is not portable and will break on other machines.
